# Group 3 EDA — 주자 상황 및 경기 중요도

원본 노트("3번 EDA")를 바탕으로, 모든 수치를 실제 코드 재실행으로
재검증하고 리포트 구조를 재구성한 버전이다. 실행 코드는
[`run_eda.py`](run_eda.py) (재실행: `python reports/eda_group3/run_eda.py`,
실행 로그 원본은 [`eda_run_log.txt`](eda_run_log.txt)). 이 문서의 모든
수치는 그 로그와 `tables/*.csv`에서 그대로 가져왔다 — 추정치는 없음.

데이터: `data/train.csv` (2019~2024, 1,475,092행). `test.csv`는 사용하지
않았다.

**원본 노트와의 차이점**: 거의 모든 수치가 재검증 결과 일치했다. 한
가지만 고쳤다 — 원본의 "기대 승률 약 50% 구간: 53.12%"를 재현할 때,
단순히 45~55% 구간으로 자르면 52.95%가 나와 원본과 달랐다. 10분위로
정밀하게 나눠보니 원본이 말한 53.12%는 정확히 **40~50번째 백분위수
구간**(48.3~52.7)의 값이었다 — §7에 10분위 표를 그대로 실어 정확한
근거를 남겼다.

## 0. 담당 컬럼 8개

| 컬럼 | 설명 |
|---|---|
| `runner_on_1b`/`_2b`/`_3b` | 각 베이스 주자 여부 (0/1) |
| `num_runners_on` | 출루 주자 수 (0~3) |
| `base_state` | 주자 배치 코드 (`___`, `1__`, `_2_`, `__3`, `12_`, `1_3`, `_23`, `123`) |
| `home_win_expectancy` / `away_win_expectancy` | 홈/원정팀 기대 승률 |
| `li` | 현재 투구 상황의 중요도(leverage index) |

`home_win_expectancy`, `away_win_expectancy`는 제구 성공 확률이 아니라
**경기 승리 확률**이다 — 혼동 주의.

## 2. 구조적 불변식 검증 ([`01_invariant_checks.csv`](tables/01_invariant_checks.csv))

전 행(n=1,475,092)에 대해:

| 검사 | 위반 건수 |
|---|---|
| `runner_on_1b/2b/3b ∈ {0,1}` | 0 |
| `num_runners_on ∈ [0,3]` | 0 |
| `num_runners_on == runner_on_1b + runner_on_2b + runner_on_3b` | 0 |
| `base_state`가 세 주자 여부와 정확히 일치 | 0 |

**결론: `runner_on_1b`, `runner_on_2b`, `runner_on_3b`, `num_runners_on`,
`base_state` 5개 컬럼은 동일한 주자 상황을 5가지 형태로 표현한 것으로,
정보량 관점에서 완전 중복이다.** 선형/로지스틱 모델에 5개를 동시에
넣으면 완전 다중공선성이 발생한다(§8).

`home_win_expectancy + away_win_expectancy`는 99.9~100.1 범위(반올림
오차)이고 상관계수 **-0.9999998** — 사실상 완전한 보완 관계, 두 변수를
동시에 쓸 필요가 없다.

## 8. 변수 중복과 모델링 주의사항

### 8a. 주자 관련 변수 (완전 중복, §2에서 검증)

`runner_on_1b/2b/3b`, `num_runners_on`, `base_state` 5개는 같은 정보의
5가지 표현이다. 다음 중 하나를 선택하는 것이 적절하다:
- 방법 A: `base_state`를 범주형으로 사용
- 방법 B: 주자 여부 3개만 사용
- 방법 C: 주자 여부 + 파생변수(득점권 여부 등) 사용, `base_state`/
  `num_runners_on` 제외

트리 계열 모델은 5개를 모두 넣어도 정보 중복으로 변수 중요도가 분산될
뿐 성능이 깨지진 않지만, 제거 전후 성능 비교는 해볼 가치가 있다.

### 8b. 기대 승률

`home_win_expectancy`/`away_win_expectancy`는 완전한 보완 관계
(상관계수 -0.9999998)이므로 동시에 쓸 필요 없음. §7에서 확인했듯
`pitcher_team_win_expectancy`(투수 관점 변환)가 원본 `home_win_expectancy`
보다 target과의 상관이 13배 크다 — 두 원본 대신 이 파생 변수를
사용하는 것을 권장.

### 8c. li

오른쪽 꼬리가 긴 분포. §6에서 확인한 비선형(역U자) 관계 때문에 원본값
그대로(트리 모델) 또는 구간화가 `log1p(li)` 단순 변환보다 관계를 더
잘 반영할 가능성이 있다 — validation에서 비교 필요.

| 변수 | 계산 | 근거 |

## 12. 팀 회의용 핵심 결론

1. **관찰**: 주자 관련 5개 컬럼(`runner_on_1b/2b/3b`, `num_runners_on`,
   `base_state`)은 수학적으로 완전히 중복이다.
   **근거**: §2 — 전 행에서 `num_runners_on == sum(flags)`,
   `base_state`가 flags와 정확히 대응(위반 0건).
   **해석**: 5개가 같은 정보를 5가지로 표현한 것.
   **다음 action**: 선형 모델용은 하나만 선택, 트리 모델은 제거 전후
   ablation. 지금 삭제 확정하지 않음.

2. **관찰**: 만루가 8개 주자 배치 조합 중 성공률이 가장 낮고(51.61%),
   3루만 있을 때가 가장 높다(53.61%) — 차이 1.99%p.
   **근거**: §4 표.
   **해석**: 이닝·카운트·점수차 등이 섞여 있어 인과 단정은 아니지만,
   압박이 큰 만루 상황에서 제구가 흔들리는 경향과 일치.
   **다음 action**: `bases_loaded`, `runner_in_scoring_position`을
   validation에서 검증.

3. **관찰**: `li`는 target과의 단순 상관은 거의 0(0.0043)이지만, 구간별로
   보면 중간 수준(1.0~2.0)에서 성공률이 가장 높고 양 극단에서 낮아지는
   비선형 관계가 뚜렷하다.
   **근거**: §6 표 — <=0.5 51.69% → 1.0~2.0 52.90%(최고) → >3.0 51.81%.
   **해석**: `li`를 단순 선형 변수로 넣으면 이 역U자 관계를 놓칠 수 있음.
